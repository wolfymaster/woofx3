# Bundled modules

Build-time-only source for modules that ship inside the barkloader binary.
**Nothing here is read at runtime** — `barkloader/app/build.rs` zips each
`modules/*/` directory, hashes it, and embeds the archive, so a release has no
`modules/` directory to be missing and first run needs no network.

Adding a bundled module is adding a directory with a `manifest.json`. The build
scans generically; no list to update, no service code to touch.

`bundled.lock.json` is generated by that build step and committed so a change to
bundled content shows up in review as a digest change rather than only as a
binary that differs.

The single `woofx3` module id is reserved for these declarations
(`manifest_validate.rs::SYSTEM_MODULE_ID`) and cannot be installed from an
upload. Group entries for the UI with per-entry `taxonomy`, not by minting new
module ids.

Not to be confused with `barkloader/modules/` — barkloader's *runtime* local
repository for installed module content (`DEFAULT_MODULE_DIR`, resolved against
its working directory). This directory is build-time source only.
